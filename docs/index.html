1. Overview

Pinecone publishes one base skills library — pinecone-io/skills — that is intentionally environment-agnostic. The base repo fans out to one downstream plugin repo per agentic IDE: Claude Code, Cursor, Gemini CLI, Kiro, and (this repo) Codex. Each downstream repo packages the skills into that IDE's plugin format and runs a "contextualize" GitHub Action to adapt incoming changes to the local conventions before a maintainer merges.

3. Sync pipeline (upstream → here)

The base repo's .github/workflows/sync-skills.yml fires on every push to main that touches skills/**, plus on manual workflow_dispatch. It diffs HEAD~1..HEAD (or — on dispatch — every file under skills/), copies the changed files into this repo, opens a PR on branch sync/skills-<run_id>, and labels it skill-sync.

A PLUGIN_SYNC_PAT personal access token gives the upstream workflow push permission on this repo. The PR body lists the changed files and links to the upstream Actions run. The contextualize workflow takes it from there.

Adding this repo to the matrix: once pinecone-io/pinecone-codex-plugin exists on GitHub, the upstream sync-skills.yml needs the repo added to two places — the workflow_dispatch.inputs.target_repo choice list and the strategy.matrix.target array. That edit lives in pinecone-io/skills, not here.

4. Contextualization workflow

.github/workflows/contextualize-skills.yml triggers on every pull_request event (opened or synchronized), but the if: gate skips anything whose branch doesn't start with sync/skills-. A second guard skips runs whose last commit was authored by the bot itself, so re-pushes during contextualization don't loop.

When the gates pass, the workflow invokes anthropics/claude-code-action@v1 with a prompt that inlines the Codex conventions (no separate CLAUDE.md/AGENTS.md needed). The Claude action gets a tight allowed-tools whitelist: Read, Write, Edit, Bash(git:*), Bash(gh pr comment:*), Bash(mv:*), Bash(python3:*).

What the bot changes

  • Strips the pinecone- prefix from name: frontmatter values and from skill directory names.
  • Rewrites cross-skill references in skill bodies to the pinecone:<skill> invocation form.
  • Removes any allowed-tools frontmatter (Claude-only).
  • Removes any AskUserQuestion references (Claude-only tool name).
  • De-emphasizes .env fallback wording (Codex inherits the shell env).
  • Rewrites source_tag= literals in Python scripts to codex_plugin:<skill>[_<operation>].
  • Runs python3 scripts/check_all.py and fixes anything it flags inside skills/.

What the bot does NOT touch

  • .codex-plugin/, .agents/plugins/, .mcp.json, .github/, scripts/, README.md, CHANGELOG.md, docs/, LICENSE.
  • Python logic inside scripts/*.py — only the source_tag string literal is rewritten.
  • The meaning of any skill — only structure, terminology, naming, and source-tag prefixes.

Test marketplace

After contextualization, a separate step generates test-marketplace/.agents/plugins/marketplace.json pointing at the PR's branch via a git-subdir source. A reviewer can install the PR by adding that path as a marketplace, exercising the exact plugin tree the PR ships.

The release workflow deletes test-marketplace/ on merge so it never ships to main.

5. Validators

All validators are plain Python 3 — stdlib only, no uv or pyyaml needed in CI. Run the whole suite locally: 

python3 scripts/check_all.py
ScriptWhat it enforces
check_manifest.py .codex-plugin/plugin.json parses; has name, version, description, skills; name is lowercase kebab-case; version is semver; every path field (skills, mcpServers, hooks, apps, interface.composerIcon, interface.logo, interface.screenshots) starts with ./ and resolves to a real file; interface.brandColor is #RRGGBB if present.
check_marketplace.py .agents/plugins/marketplace.json parses; each entry has name, policy.installation, policy.authentication; each local source.path starts with ./, stays inside the repo, points at a directory containing .codex-plugin/plugin.json.
check_skills.py Every skills/*/SKILL.md has YAML frontmatter with name and description; name matches the directory name and does NOT start with pinecone- (catches un-contextualized syncs); no allowed-tools key (Claude-only); description is a single line, ≤ 1000 chars; body has no AskUserQuestion reference.
check_source_tags.py Every source_tag= literal in skills/**/*.py matches ^codex_plugin:[a-z0-9_]+(:[a-z0-9_]+)?$. Catches leakage from pinecone_skills:*, claude_code_plugin:*, cursor_plugin:*, etc.
check_links.py Every relative markdown link in skill docs (and README.md) resolves to an existing file inside the repo. HTTP(S), mailto, and anchor-only links are skipped.
check_all.py Thin wrapper that runs all of the above and aggregates exit codes. CI calls this.
If a validator fails in CI: the failure message names the file and the rule that tripped. Fix the file (don't relax the rule unless you're changing the conventions deliberately). Common culprits — incoming PR has name: pinecone-foo in a SKILL.md (the contextualize bot didn't run, or the gate skipped it), or a Python script kept its upstream source_tag prefix.

6. Release workflow

.github/workflows/release.yml fires on pull_request.types: [closed] against main and only proceeds when github.event.pull_request.merged == true. Bump type is decided by PR labels:

  • bump:major → X.0.0
  • bump:minor → X.Y+1.0
  • neither (default) → X.Y.Z+1

The job:

  1. Reads .codex-plugin/plugin.json, bumps the version, writes it back.
  2. Generates changelog bullets from gh pr view --json commits --jq '.commits[].messageHeadline', filtering out chore: and create-pull-request entries.
  3. Inserts a ## [X.Y.Z] - YYYY-MM-DD block after the # Changelog header.
  4. Deletes test-marketplace/ if the contextualize workflow left one behind.
  5. Commits as github-actions[bot], pushes the version-bump commit and a v<version> tag.
  6. Creates a GitHub release with auto-generated notes.

7. Codex plugin spec essentials

.codex-plugin/plugin.json shape

{
  "name": "pinecone",              // required, lowercase kebab-case
  "version": "0.1.0",              // semver
  "description": "...",            // user-facing summary
  "skills": "./skills/",           // path, must start with ./
  "mcpServers": "./.mcp.json",     // path, must start with ./
  "interface": {
    "displayName": "Pinecone",
    "category": "Productivity",
    "capabilities": ["Read", "Write"],
    "defaultPrompt": ["Use Pinecone to ...", "..."],
    "brandColor": "#10A37F"
  }
}

Path rules: every path is relative to the plugin root, must start with ./, and must stay inside the plugin root. Assets (icons, logos, screenshots) belong under ./assets/ when present.

.agents/plugins/marketplace.json shape

{
  "name": "pinecone-codex-plugins",
  "interface": { "displayName": "Pinecone for Codex" },
  "plugins": [
    {
      "name": "pinecone",
      "source": { "source": "local", "path": "./" },
      "policy": {
        "installation": "AVAILABLE",
        "authentication": "ON_INSTALL"
      },
      "category": "Productivity"
    }
  ]
}

For Git-backed entries the source object uses "source": "git-subdir" with url, path, and a ref or sha. The contextualize workflow's per-PR test marketplace uses that shape.

8. Adding a new skill manually

Most skills land via the upstream sync. If you need to add one directly:

  1. Create skills/<skill-name>/SKILL.md. The directory name is the slug (bare, no pinecone- prefix).
  2. Frontmatter must contain name: <same-as-directory> and a single-line description. No allowed-tools key.
  3. If the skill ships Python helpers, put them in skills/<skill-name>/scripts/. Every Pinecone(...) call that sets source_tag= must use codex_plugin:<skill>[_<operation>].
  4. Run python3 scripts/check_all.py. Iterate until green.
  5. Update README.md's skills table.
  6. Open a PR. validate.yml will run; the contextualize workflow won't fire (branch isn't sync/skills-*). Merge once green and the release workflow will tag a new version.

9. Troubleshooting

SymptomLikely cause / fix
check_skills.py fails: "name still has pinecone- prefix" An upstream sync landed without the contextualize workflow running (the branch may not start with sync/skills-, or the bot's last commit caused the skip-if-bot guard to fire on a re-push). Re-run the workflow manually or edit the SKILL.md by hand.
check_skills.py fails: "allowed-tools is a Claude Code field" Upstream copied a Claude-plugin SKILL.md by mistake. Strip the allowed-tools: frontmatter line.
check_source_tags.py fails with claude_code_plugin: or pinecone_skills: The contextualize bot didn't rewrite a tag. Edit the offending .py file and change the prefix to codex_plugin:. Do not change the suffix.
check_links.py fails on a references/foo.md path The reference file was moved or renamed; update the link or restore the file.
Contextualize workflow skipped on a sync PR Check that the branch name starts with sync/skills- exactly. The skip-if-bot guard will also block runs whose last commit is authored by github-actions[bot]; push an empty commit as a human to re-trigger.
Release ran but didn't tag The release job only runs when the PR is merged (not just closed). Check the PR's merge state and the workflow logs for the "Determine bump type" step.
MCP not loading after install Codex needs npx on PATH; install Node.js. Confirm PINECONE_API_KEY is exported in the same shell that launched Codex.
